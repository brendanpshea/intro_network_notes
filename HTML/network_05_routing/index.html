Routing, Switching, and Network Infrastructure

Routing tables, static and dynamic routing, NAT/PAT, firewalls, VLANs, and enterprise network design.

Introduction

Module 4 focused on IP addressing and subnetting. This chapter builds on that foundation by showing how packets actually move across multiple networks, how routers choose paths, and how organizations secure and segment their infrastructure at the network edge and inside the LAN.

The chapter moves from Layer 3 routing into boundary services such as NAT and firewalls, then finishes with VLANs and trunking. Those topics matter together because real networks rarely stop at a single switch or a single subnet.

Review from Module 4

Module 4 explained that IP addresses identify networks and hosts, while MAC addresses identify hardware on a local link. Routers use the destination IP to decide where a packet should go next. That decision is what makes communication across separate networks possible.

Core Distinction

Switches forward frames using MAC addresses at Layer 2. Routers forward packets using IP addresses at Layer 3.

Learning Outcomes

After completing this module, you will be able to:

  • Explain how routers forward packets using routing tables and longest prefix match.
  • Compare static routing, dynamic routing, and default routes.
  • Interpret traceroute output and common router diagnostic commands.
  • Describe RIP, EIGRP, OSPF, and BGP at a high level.
  • Explain NAT, PAT, firewall types, and DMZ placement.
  • Design and secure VLAN-based segmentation with trunking and voice VLANs.

Routing Foundations

Routing Foundations

Router: Gateway Between Networks

A router connects different networks at Layer 3. Each interface belongs to a different subnet, and the router uses the destination IP address to decide the best outgoing interface or next hop. Every packet passing through a router has its TTL decremented by one.

Why Routers Matter

Switches keep traffic local inside a broadcast domain. Routers move traffic between broadcast domains and can apply policy, translation, and filtering at the edge.

Routing Tables and Path Selection

Every router keeps a routing table containing known destination networks, next hops, and metrics. When a packet arrives, the router reads the destination IP, searches the table, and selects the most specific matching entry. That rule is called longest prefix match. 

graph TD
    A["Packet arrives"] --> B["Read destination IP"]
    B --> C["Search routing table"]
    C --> D["Find longest prefix match"]
    D --> E["Forward to next hop or exit interface"]

Figure 3: Routing is a simple decision chain. The router never guesses; it matches the destination address against known prefixes and forwards accordingly.

Static and Default Routes

Static Routes

Static routes are manually configured and stay in place until an administrator changes them. They are predictable and useful for small or tightly controlled networks.

ip route 10.0.0.0 255.0.0.0 192.168.1.1
Default Route

The route of last resort handles anything not matched more specifically.

ip route 0.0.0.0 0.0.0.0 203.0.113.1

Routing Table Example

A real routing table usually includes directly connected networks, static entries, and a default route. The router prefers the most specific valid entry; if no specific route exists, it falls back to the default route.

Packet Forwarding Process

A router changes the Layer 2 header at each hop because it has to deliver the packet across the next local link. The Layer 3 source and destination addresses stay the same end-to-end, but the source and destination MAC addresses are replaced at every hop. 

graph LR
    A["Incoming frame
Src MAC / Dst MAC
Src IP / Dst IP"] --> R["fa:fa-wifi Router
Lookup + TTL--"]
    R --> B["Outgoing frame
New Src MAC / New Dst MAC
Same Src IP / Same Dst IP"]

Figure 4: The router rewrites Layer 2 addresses while preserving Layer 3 addresses. That is why a packet can cross many routers without changing its IP identity.

Fragmentation and MTU

The MTU is the largest packet payload a link can carry. Standard Ethernet uses an MTU of 1500 bytes. If a packet is too large, it must be fragmented or dropped. Modern systems try to avoid fragmentation by using Path MTU Discovery.

Why Fragmentation Hurts

Fragmentation adds processing overhead, and if a single fragment is lost, the entire packet has to be retransmitted.

Router Configuration and Tools

Basic Router Configuration

At minimum, a router needs interface IP addresses, enabled interfaces, a hostname, and whatever routes are necessary to reach other networks. In practice, administrators also configure passwords and save the running configuration after changes.

tracert and traceroute

tracert on Windows and traceroute on Linux/macOS use TTL manipulation to reveal each hop along a path. The tool sends probes with increasing TTL values; each router along the path decrements the TTL and returns an ICMP Time Exceeded response until the destination is reached.

Dynamic Routing Protocols

Dynamic Routing Protocols

Dynamic Routing Overview

Static routes are simple, but they do not adapt when links fail or new paths appear. Dynamic routing protocols share reachability information automatically and converge on new paths when the topology changes. Inside an organization they are called IGPs; between organizations, the internet uses BGP, an EGP. 

graph LR
    subgraph A["AS 100 - Your Company"]
        R1["fa:fa-wifi Router"] --- R2["fa:fa-wifi Router"]
    end
    subgraph B["AS 200 - ISP"]
        R3["fa:fa-wifi Router"] --- R4["fa:fa-wifi Router"]
    end
    R2 ==>|"BGP"| R3

Figure 6: OSPF, RIP, and EIGRP are IGPs inside one organization. BGP is the inter-AS protocol used to exchange routes between organizations.

RIP and EIGRP

RIP

RIP uses hop count. It is simple, but it ignores link speed and caps routes at 15 hops.

EIGRP

EIGRP uses bandwidth and delay, converges quickly, and supports more advanced balancing behavior.

OSPF

OSPF is an open standard, link-state protocol. It builds a topology map and calculates route cost using bandwidth. Large networks use hierarchical areas with an Area 0 backbone and area border routers connecting other areas to the backbone. 

graph TD
    A0["Area 0 Backbone"]
    A1["Area 1"]
    A2["Area 2"]
    A0 --- A1
    A0 --- A2

Figure 7: OSPF scales through hierarchy. Areas reduce route flooding and keep topology calculations manageable.

BGP

BGP is the protocol of the internet. It is used to exchange routing information between autonomous systems and is policy-driven rather than purely metric-driven. Enterprises use BGP when they need multihoming or control over upstream paths.

    C["fa:fa-building Company AS"] --> I1["fa:fa-wifi ISP Alpha"]
    C --> I2["fa:fa-wifi ISP Beta"]
    I1 --> N["fa:fa-cloud Internet"]
    I2 --> N

Figure 8: BGP multihoming. A company can connect to multiple ISPs for redundancy and policy control.

Route Selection and Administrative Distance

When multiple sources know the same route, Administrative Distance decides which source to trust. Lower is better. Direct routes beat static routes, and static routes beat learned routing protocols.

Route SourceAdministrative Distance
Directly Connected0
Static Route1
EIGRP (internal)90
OSPF110
RIP120

Edge Routers and Network Boundaries

The edge router sits at the demarcation point between the internal network and the ISP. It can route, translate addresses, and enforce policy before traffic leaves or enters the organization.

Network Address Translation (NAT)

NAT translates private addresses into public addresses. It is one answer to IPv4 address exhaustion and lets many internal hosts share fewer public addresses.

PAT: Port Address Translation

PAT lets many private devices share a single public IP address by tracking unique source ports. This is the most common home and small business setup.

Firewall Uses and Types

Firewalls filter traffic according to policy. Most use a default-deny stance and only allow traffic that has been explicitly permitted. Stateful inspection and application awareness improve on simple packet filtering by tracking sessions and higher-layer data.

Firewall TypeSummary
Packet FilteringStateless, checks IPs and ports
Stateful InspectionTracks connection state
Application FirewallInspects application payloads
NGFWAdvanced inspection, IPS, and policy enforcement

Firewall Placement and DMZ

A DMZ is a screened subnet for public-facing servers. If a web or mail server in the DMZ is compromised, the internal LAN remains protected by the inner firewall.

VLAN Segmentation and Trunking

VLAN Segmentation and Trunking

Introduction to VLANs

VLANs divide one physical switch into multiple logical broadcast domains. That improves security and performance because traffic from one VLAN does not automatically reach devices in another VLAN. If traffic needs to cross VLAN boundaries, a router or Layer 3 switch must handle it.

VLAN Trunking and 802.1Q

A trunk carries traffic for multiple VLANs between switches or between a switch and a router. The 802.1Q tag identifies the VLAN so the receiving switch can place the frame in the correct logical network.

Figure 14: Trunk links transport multiple VLANs over one physical connection using 802.1Q tagging.

Voice VLANs

Voice VLANs keep phone traffic separate from general data traffic while still letting a desk phone act as a pass-through for the workstation behind it. That keeps voice traffic prioritized and simplifies cabling.

Why Voice VLANs Help

Voice is sensitive to delay and jitter. Giving it a dedicated VLAN and higher QoS priority keeps calls stable under load.

Native VLAN and Security

Untagged traffic on a trunk belongs to the native VLAN. If the two ends of a trunk disagree on the native VLAN, or if default VLAN 1 is used carelessly, the network can be exposed to VLAN hopping risks. Good practice is to move the native VLAN away from the default and keep it consistent on both ends.

Module Summary

Module Summary

Module 5 Summary

Routing

  • Routers forward packets at Layer 3 using routing tables.
  • Longest prefix match selects the best route.
  • Static routes and default routes are simple and predictable.
  • Dynamic routing protocols adapt automatically to change.

NAT and Security

  • NAT and PAT conserve IPv4 addresses.
  • Firewalls enforce policy at the edge and between segments.
  • DMZs isolate public servers from the internal LAN.

VLANs

  • VLANs create logical broadcast domains on the same switch.
  • 802.1Q trunks carry multiple VLANs between devices.
  • Voice VLANs prioritize voice traffic and reduce cabling complexity.
  • Native VLAN handling matters for both compatibility and security.

Protocol Hierarchy

  • RIP, EIGRP, OSPF, and BGP serve different scopes.
  • Administrative Distance determines which learned route is trusted.
  • Enterprise design often combines routing, segmentation, and security at the edge.
